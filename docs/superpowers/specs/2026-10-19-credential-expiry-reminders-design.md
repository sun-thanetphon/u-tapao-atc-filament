# เตือนวันหมดอายุใบอนุญาต / ใบรับรองแพทย์ / rating / ภาษา (Design)

วันที่: 2026-10-19 · สถานะ: รอผู้ใช้ตรวจสเปก

## เป้าหมาย

ส่งอีเมลเตือน **เจ้าตัวคนเดียว** เมื่อเหลือไม่เกิน 3 เดือน (90 วัน) ก่อนหมดอายุของแต่ละรายการ
ในชีต Google "ผู้ถือใบอนุญาตพนักงานควบคุมการจราจรทางอากาศ สนามบินนานาชาติอู่ตะเภา" (~28 คน)
โดยไม่ต้องกรอกข้อมูลซ้ำ: **ชีตเป็นแหล่งข้อมูลหลัก** ระบบอ่านอย่างเดียว

## สิ่งที่ผู้ใช้ตกลงแล้ว

- ส่งถึงเจ้าตัวอย่างเดียว (ไม่ cc หัวหน้า/admin)
- เตือนที่ 3 เดือน (90 วัน) รอบเดียวต่อรายการต่อวันหมดอายุ
- ระบุตัวตนด้วยชื่อ + นามสกุลที่ตรงกับบัญชีในระบบ ใช้อีเมลจากบัญชี
- ร่างการทำงาน 5 ข้อ (อ่านชีตรายวัน, เมลเดียวรวมทุกรายการของคน, จำว่าเตือนแล้ว, หน้า admin, cron) ผ่านแล้ว
- มีโหมดดูตัวอย่างก่อนส่งจริง (ครั้งแรกคนที่เหลือ < 90 วันอยู่แล้วจะได้เมลทันที)

## ข้อมูลในชีต (ตรวจแล้ว 2026-10-19)

ชีตเปิดแบบ "ใครมีลิงก์ก็ดูได้" ดึงเป็น CSV ได้ที่ `.../export?format=csv&gid=0` แถว 1 เป็นหัวเรื่อง แถว 2 เป็นหัวคอลัมน์ ข้อมูลเริ่มแถว 3

| คอลัมน์ (index) | ความหมาย |
| --- | --- |
| 1 | Name of Holder เช่น `น.ต.สมคิด สุนทรเพราะ` (ยศติดชื่อ ไม่มีช่องว่าง) |
| 2 | เลขใบอนุญาต |
| 3 | Ratings (ข้อความ ไม่ใช่วันที่) |
| 6 | Rating Expiry |
| 8 | Validity of licence |
| 10 | Validity of Medical Class 3 |
| 13 | Language Proficiency: Valid Until |

คอลัมน์ "day left" (7, 9, 11, 14) ชีตคำนวณเอง **ระบบไม่ใช้** คำนวณใหม่จากวันที่เองเสมอ
วันที่รูปแบบ `August 31, 2029` (`F j, Y`) แถวว่างท้ายตารางข้าม

หมายเหตุสำหรับผู้ใช้: ชีตนี้มีชื่อ เลขใบอนุญาต และวันหมดอายุใบรับรองแพทย์ของทุกคน
และเปิดให้ทุกคนที่มีลิงก์ดูได้ แนะนำจำกัดสิทธิ์ ซึ่งจะกระทบวิธีดึงข้อมูล (ดู "ความเสี่ยง")

## การทำงาน

### 1. ดึงและแปลงชีต — `App\Support\CredentialSheet`
- ดึง CSV ด้วย `Http` timeout 15 วินาที จาก `CREDENTIAL_SHEET_ID` และ `CREDENTIAL_SHEET_GID` ใน `.env`
  (ไม่ใส่ ID ชีตลงโค้ด/สเปก/git)
- แปลงแต่ละแถวเป็นรายการ 4 ชนิด: `rating`, `licence`, `medical`, `language`
  - ช่องวันที่ว่าง = ไม่มีรายการนั้น (ไม่ใช่ error)
  - ช่องที่มีหลายวันที่ (หลายบรรทัด) ใช้ **วันที่เร็วที่สุด**
  - ช่องที่อ่านเป็นวันที่ไม่ได้ → เก็บเป็น "อ่านไม่ได้" แสดงในหน้า admin ไม่ส่งเมล
- ดึงไม่สำเร็จ / ได้ไม่ใช่ CSV / ไม่มีหัวคอลัมน์ที่คาดไว้ → หยุดทั้งรอบ ไม่ส่งอะไร ไม่บันทึกอะไร log เฉพาะประเภทข้อผิดพลาด
- ตรวจหัวคอลัมน์ตามชื่อ (`Rating Expiry`, `Validity of licence`, `Validity of Medical Class 3`, `Valid Until`)
  ไม่ใช้ตำแหน่งตายตัว เพื่อให้เพิ่มคอลัมน์ในชีตได้โดยไม่พัง

### 2. จับคู่คนกับบัญชี — `App\Support\CredentialMatcher`
- ทำให้เป็นรูปมาตรฐาน: ตัดช่องว่างทุกชนิด + ตัวพิมพ์เล็ก + Unicode NFC
- ชื่อในชีตเมื่อทำมาตรฐานแล้ว **ลงท้ายด้วย** `firstname+lastname` ของผู้ใช้ที่ `active()` และไม่ถูกลบ → จับคู่ได้ (ยศอยู่ข้างหน้าจึงไม่ต้องรู้รายการยศ)
- เจอ 0 คน → สถานะ `ไม่พบบัญชี`; เจอ > 1 คน → `ชื่อซ้ำ ไม่ส่ง`; เจอ 1 คนแต่ไม่มีอีเมล/อีเมลไม่ถูกต้อง → `ไม่มีอีเมล`
- สามสถานะนี้ไม่ส่งเมลและแสดงในหน้า admin พร้อมเหตุผล (ไม่ปล่อยเงียบ)

### 3. ตัดสินว่าจะเตือนอะไร — `App\Support\CredentialReminder`
- รายการเข้าเงื่อนไขเมื่อ `วันหมดอายุ - วันนี้ ≤ 90 วัน` (รวมที่หมดอายุไปแล้ว ติดป้าย "หมดอายุแล้ว")
- ตารางใหม่ `credential_reminders`: `id, user_id (FK), item (string 16), expires_on (date), sent_at, created_at`
  unique `(user_id, item, expires_on)` ต่ออายุแล้ววันใหม่ = แถวใหม่ = เตือนรอบใหม่ได้
- รอบหนึ่ง: รวมรายการที่ยังไม่มีแถว `credential_reminders` ของแต่ละคนเป็น **เมลฉบับเดียวต่อคน**
- จองสิทธิ์แบบ `insertOrIgnore` ก่อนส่ง (กันรัน cron ซ้อนกัน) ส่งไม่สำเร็จ → ลบแถวที่จองไว้ เพื่อให้ลองใหม่วันถัดไป
  (ส่งสำเร็จแล้วค่อยปล่อยแถวไว้เป็นหลักฐานว่าเตือนแล้ว)

### 4. ส่งเมล
- `App\Mail\CredentialExpiryMail` (markdown view `mail.credential-expiry`) ภาษาไทย
  ตาราง: รายการ · วันหมดอายุ · เหลือกี่วัน/หมดอายุแล้ว ผู้รับเป็น To คนเดียว ไม่มี BCC
- ส่งผ่าน `SafeMail::send` นับโควตาด้วย `MailQuota` เดิม ตรวจ `MailQuota::canUse(1, config('mail.daily_cap_for_reminders', 40))` ก่อนส่งแต่ละฉบับ
  โควตาหมด → หยุด ที่เหลือส่งวันถัดไป (ไม่มีแถวจอง จึงไม่ตกหล่น)
- โหมดทดสอบ: ถ้าตั้ง `MAIL_REMINDER_TEST_RECIPIENT` ส่งทุกฉบับไปที่อยู่นั้นเท่านั้น (หัวเรื่อง `[ทดสอบ]` ไม่ใส่ชื่อผู้รับจริง) และ **ไม่จองสิทธิ์** ค่าไม่ถูกต้อง = ห้ามส่งให้ใครเลย (ตามแบบ `DocumentNotifier`)
- log เฉพาะจำนวน (คนที่ส่ง, ข้าม, ล้มเหลว) ห้ามมีชื่อ อีเมล หรือวันหมดอายุของใบรับรองแพทย์

### 5. คำสั่งและตัวตั้งเวลา — `credentials:remind`
- `php artisan credentials:remind --dry-run` พิมพ์ตารางว่าใครจะได้เมลรายการไหน และรายชื่อที่ส่งไม่ได้ **ไม่ส่ง ไม่บันทึก**
  (ใช้ตรวจก่อนเปิดใช้จริงครั้งแรก)
- `php artisan credentials:remind` ส่งจริง
- ตั้ง cron ใน hPanel รายวัน เช่น `0 7 * * * cd ~/domains/u-tapaoatc.com && php artisan credentials:remind >> /dev/null 2>&1`
  (เวลาไทย: ตรวจเขตเวลา server ตอน deploy) ไม่ใช้ `schedule:run` ทุกนาทีเพื่อลดภาระโฮสต์
- ผมตั้ง cron ผ่าน SSH ให้ได้ **เมื่อคุณอนุญาต** ตอน deploy

### 6. หน้า admin — Filament page "วันหมดอายุใบอนุญาต" (กลุ่ม Accounts)
- เห็นได้เฉพาะ super-admin และ admin (ข้อมูลสุขภาพ) ผู้ใช้ทั่วไปไม่เห็นเมนูและเข้า URL ตรงไม่ได้ (403)
- ตาราง: ชื่อ · รายการ · วันหมดอายุ · เหลือกี่วัน · สถานะ (เตือนแล้ว/ยังไม่ถึง/ส่งไม่ได้: เหตุผล) เรียงตามเหลือน้อยสุดก่อน
- ดึงชีตสดแล้วแคช 10 นาที มีปุ่ม "รีเฟรช"
- ส่วนที่สอง: รายชื่อที่ส่งไม่ได้ (ไม่พบบัญชี / ชื่อซ้ำ / ไม่มีอีเมล / วันที่อ่านไม่ได้) พร้อมเหตุผล
- ปุ่ม "ส่งอีเมลทดสอบถึงฉัน" ส่งตัวอย่างเมลหนึ่งฉบับถึงอีเมลของผู้กดเอง ไม่จองสิทธิ์
- หน้านี้ **อ่านอย่างเดียว** ไม่แก้ข้อมูล (แก้ที่ชีต)

## ความเสี่ยงและข้อจำกัด

- **ถ้าจำกัดสิทธิ์ชีต** การดึง CSV แบบสาธารณะจะพัง (ได้หน้า login แทน → ระบบหยุดรอบและขึ้น error ในหน้า admin)
  ทางออกคือ service account ของ Google (มีใช้อยู่ในโปรเจกต์ Differ2) นอกขอบเขตรอบนี้ แจ้งก่อนจำกัดสิทธิ์
- ชื่อไม่ตรงกันระหว่างชีตกับบัญชี → ไม่ได้เมล แต่เห็นในรายชื่อที่ส่งไม่ได้
- โควตาเมลโฮสต์ 100 ฉบับ/วัน ใช้ร่วมกับเมลรีเซ็ตรหัสผ่าน/ลงทะเบียน/เอกสาร จึงจำกัดเตือนไว้ 40 ฉบับ/วัน
  (~28 คน เมลเดียวต่อคน จึงพอ)
- ไม่มี queue worker: ส่งแบบ synchronous ในคำสั่ง cron (ไม่กระทบผู้ใช้เว็บ)
- แก้ชีตแล้วระบบเห็นรอบถัดไป (ไม่เรียลไทม์)

## การทดสอบ (Feature/Unit, รันใน Docker)

- `CredentialSheetTest`: CSV ตัวอย่างไม่มีข้อมูลจริง (`Http::fake`): แปลงวันที่ถูก, ช่องว่าง, หลายวันที่ในช่องเดียวใช้เร็วสุด, วันที่เสีย, หัวคอลัมน์หาย/ได้ HTML → หยุดรอบ
- `CredentialMatcherTest`: ยศติดชื่อ, ช่องว่างต่างกัน, ชื่อซ้ำ, ไม่มีบัญชี, บัญชีไม่มีอีเมล, บัญชี suspended/ถูกลบ ไม่นับ
- `CredentialReminderTest` (`Mail::fake`): เตือนที่ 90 วันพอดี, 91 วันไม่เตือน, เมลเดียวรวมหลายรายการ, รันซ้ำไม่ส่งซ้ำ, วันหมดอายุใหม่ = เตือนใหม่, ส่งล้มเหลวแล้วลองใหม่ได้, โควตาหมดแล้วหยุด, โหมดทดสอบไม่จองสิทธิ์และไม่เผยผู้รับจริง, `--dry-run` ไม่ส่งไม่บันทึก
- `CredentialPageTest`: user/admin/super-admin เข้าได้ตามที่กำหนด, 403 สำหรับ user ทั่วไป

## นอกขอบเขต (ไม่ทำรอบนี้)

เตือนซ้ำที่ 1 เดือน/1 สัปดาห์, สำเนาหัวหน้า, แก้ข้อมูลในเว็บ, การแจ้งเตือนในกระดิ่ง, อ่านชีตที่ไม่เปิดสาธารณะ
