# Roadmap ระบบรับทราบเอกสาร U-Tapao ATC

ปรับปรุงล่าสุด: 2026-10-28 · สถานะ: ร่าง รอผู้ใช้ตรวจ

แผนรวมทั้งระบบ ทั้งเรื่องเทคนิคและฟีเจอร์ เรียงตามความสำคัญ ไว้หยิบงานมาทำทีละชิ้น
งานแต่ละชิ้นเขียน spec และ plan ของตัวเองใน `docs/superpowers/` ตอนจะลงมือ แล้วกลับมาติ๊กที่นี่เมื่อ deploy แล้ว

## หลักที่ใช้จัดลำดับ

- ความปลอดภัยและงานที่มีเส้นตายมาก่อน แล้วค่อยฟีเจอร์ (เลือกแนวทางนี้เมื่อ 2026-10-28)
- ฟีเจอร์เน้นเป้าหมายของระบบใน `PRODUCT.md`: ทุกคนที่ต้องรับทราบได้รับทราบครบ และพิสูจน์ได้ว่าใครรับทราบอะไรเมื่อไร
- ต้องรันบนโฮสต์ร่วมเดิมได้: deploy ด้วย `git pull` ไม่มี build ไม่มี queue เมลไม่เกิน 100 ฉบับต่อวัน cron ตั้งใน hPanel
- เก็บ logic ไว้ใน `app/Support` ให้ชั้น Filament บาง เพื่อให้ย้ายไป Filament 5 ในเฟส 4 ง่าย
- การ Force ของ super-admin ต้องดูเหมือนเจ้าตัวกดรับทราบเอง ทั้งในหน้าเว็บ ไฟล์ Excel และรายงานที่พิมพ์ (ผู้ใช้ตัดสินใจ 2026-10-28) งานใดที่ทำให้แยกออกได้ต้องไม่ทำ

ขนาดงาน: **S** ไม่เกิน 1 วัน · **M** 2–4 วัน · **L** 1–2 สัปดาห์

## เฟส 0: ปิดช่องโหว่ (ทำทันที)

ณ 2026-10-28 `composer audit --locked` พบ 72 advisories ใน 20 แพ็กเกจ (critical 4, high 23)
เช่น Livewire CVE-2025-54068 และ PhpSpreadsheet ที่ใช้อ่านไฟล์อัปโหลดใน `app/Support/EmailImport.php`
ทุกตัวมีเวอร์ชันที่แก้แล้วในรุ่นหลักเดิม

- [ ] 0.1 อัปเดตแพ็กเกจในรุ่นหลักเดิม แล้ว deploy **[S]** (กำลังทำใน session แยกบน branch ของตัวเอง)

เสร็จเมื่อ: production ใช้เวอร์ชันใหม่ และ `composer audit` ไม่เหลือ critical/high ที่แก้ได้ในรุ่นหลักเดิม

## เฟส 1: ฐานระบบให้มั่นคง (ต้องเสร็จก่อน 24 ก.พ. 2027)

- [ ] 1.1 ขึ้น Laravel 13 โดยยังใช้ Filament 3 **[M]** ทำหลังเฟส 0 merge
  - เปลี่ยน PHP บนโฮสต์เป็น 8.3+ ใน hPanel
  - `flowframe/laravel-trend` ^0.5 และ `laravel/tinker` ^3.0
  - เอา `swisnl/filament-backgrounds` ออก (รุ่น 1.x รองรับถึง Laravel 12) แล้วใส่พื้นหลังหน้า login ด้วย CSS ใน `resources/css/filament-theme.css` แทน
  - ลองจำลองกับสำเนา `composer.lock` แล้ว (2026-10-28): หลังแก้สามข้อนี้ resolve ได้เป็น Laravel 13.39 + Filament 3.3.57 + Livewire 3.8.11
- [ ] 1.2 กันแพ็กเกจเก่าค้าง: `composer audit` ใน CI และ Dependabot เปิด PR อัปเดตรายเดือน **[S]** ทำหลังเฟส 0 (ไม่งั้น CI ไม่ผ่าน)
- [ ] 1.3 สคริปต์ deploy ไฟล์เดียว: backup → `git pull` → `composer install` → migrate → `optimize` และ `filament:optimize` **[S]**
  ต้องรู้ก่อนว่าโฮสต์รัน composer ผ่าน SSH ได้ไหม และ `public_html` เป็น symlink ไป `public` หรือเป็นโฟลเดอร์แยก (ถามในเฟส 0)
- [ ] 1.4 เอกสารส่งต่อ **[S]**
  - README: ตั้งเครื่อง dev ด้วย Docker, รัน test, deploy, รายการ cron ใน hPanel, ค่า env, วิธีกู้คืน backup
  - แก้ `PRODUCT.md` ส่วนที่ล้าสมัย (เรื่องปี พ.ศ./ค.ศ. แก้ไปแล้วใน commit `df8a7a5`)
- [ ] 1.5 ซ้อมกู้คืน backup บนเครื่อง local หนึ่งครั้ง **[S]**
- [ ] 1.6 เก็บกวาดโค้ดที่ไม่มีใครใช้ **[S]**
  - `app/Enums/SectionEnum.php` (ในไฟล์ประกาศชื่อเป็น `RoleEnum` ผิด)
  - `resources/views/welcome.blade.php`

เสร็จเมื่อ: production รัน Laravel 13 บน PHP 8.3+ และ deploy ได้ด้วยคำสั่งเดียว

## เฟส 2: หลักฐานที่พิสูจน์ได้

เริ่มได้เลยและทำสลับกับเฟส 1 ได้ ขอแค่ 1.1 เสร็จทันเส้นตาย

- 2.1 ตัดออก (2026-10-28): การ Force ต้องดูเหมือนเจ้าตัวกดเองตามที่ทำอยู่แล้ว
- [ ] 2.2 เก็บไฟล์ทุกฉบับและประวัติฉบับ **[M]**
  - ตารางประวัติต่อเอกสาร: รอบ วันที่ ผู้อัปโหลด หมายเหตุว่าเปลี่ยนอะไร แอดมินเปิดไฟล์รอบเก่าได้
  - ตอนนี้ `DocumentObserver::updating` ลบไฟล์เดิมทันทีที่เปลี่ยนไฟล์
  - ต้องคิดเรื่องพื้นที่ดิสก์บนโฮสต์และขนาด backup ไฟล์ ไฟล์ที่ลบไปแล้วอาจกู้ได้บางส่วนจาก backup ไฟล์รายสัปดาห์
- 2.3 ตัดออก (2026-10-28): บันทึกเวลาเปิดอ่านจะเผยว่าใครถูก Force (ไม่มีเวลาเปิดอ่าน)
- [ ] 2.4 ประวัติการกระทำของแอดมิน **[M]**
  - เอกสาร: สร้าง แก้ ลบ เผยแพร่ · ผู้ใช้: สิทธิ์ แผนก สถานะ อนุมัติสมัคร รีเซ็ตรหัสผ่าน
  - **ไม่บันทึกการ Force** (ตามหลักเรื่อง Force ด้านบน)
  - หน้าให้ super-admin กรองดู เก็บนานกว่า log การล็อกอินที่ล้างทุก 90 วัน

เสร็จเมื่อ: สำหรับทุกเอกสาร ตอบได้ว่าใครรับทราบฉบับไหน และใครเปลี่ยนอะไรในเอกสาร

## เฟส 3: ตามคนรับทราบให้ครบโดยอัตโนมัติ

- [ ] 3.1 กำหนดวันรับทราบต่อเอกสาร **[S–M]**
  ค่าเริ่มต้นเช่น 14 วันหลังเผยแพร่หรือออกฉบับใหม่ แก้ได้ สถานะ "เลยกำหนด" ขึ้นในหน้างานของผู้ใช้ หน้า Home และหน้า Follow
- [ ] 3.2 เตือนอัตโนมัติด้วย cron รายวัน **[M]**
  ใช้ `PendingDocumentsReminder` เดิม (เมลเดียวต่อคน มี cooldown ใช้โควตาเมลร่วมกับเมลอื่น) เตือนตอนใกล้ครบกำหนดและหลังเลยกำหนด
  มีโหมดทดสอบและ dry-run เหมือน `credentials:remind`
- [ ] 3.3 หน้าสถานะระบบสำหรับ super-admin **[M]**
  ผลของ cron แต่ละงานครั้งล่าสุด (backup, อัปโหลด Drive, เตือนใบอนุญาต, เตือนรับทราบ) โควตาเมลที่ใช้วันนี้ และ error ล่าสุด

เสร็จเมื่อ: ไม่ต้องกดปุ่มเตือนเองอีก และดูสถานะทั้งระบบได้จากหน้าเดียว

## เฟส 4: ย้ายไป Filament 5 (เป้าหมายกลางปี 2027 เส้นตาย 1 ม.ค. 2028)

- [ ] 4.1 ย้าย Filament 3 ไป 5 พร้อม Livewire 4 ด้วย upgrade script ของ Filament **[L]**
  ต้องตรวจ CSS ของ theme ที่ inline ไว้ เพราะชื่อ class ใน Filament 4 ขึ้นไปเปลี่ยนหลายจุด
- [ ] 4.2 เปิด 2FA ที่มีในตัว Filament 5 บังคับใช้กับ admin และ super-admin **[S]**

เสร็จเมื่อ: test ผ่านทั้งชุด หน้าตาเว็บเหมือนเดิม และแอดมินทุกคนล็อกอินด้วย 2FA

## ไอเดียที่ต้องถามผู้ใช้จริงก่อน (ยังไม่จัดเข้าเฟส)

- ช่องทางแจ้งเตือนนอกจากอีเมล เพื่อเลี่ยงโควตาและช่วยคนที่ไม่มีอีเมล: Web Push หรือ LINE Official Account (LINE Notify ปิดบริการไปแล้วตั้งแต่ 31 มี.ค. 2025)
- ไอคอนแอปบนมือถือ (PWA)
- อัปโหลดเอกสารหลายไฟล์พร้อมกัน
- รอบทบทวนเอกสาร เตือนแอดมินเมื่อถึงกำหนดทบทวน
- สิทธิ์หัวหน้าแผนก ให้ดูความคืบหน้าเฉพาะแผนกตัวเอง
